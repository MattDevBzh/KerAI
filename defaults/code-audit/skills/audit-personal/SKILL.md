# Explications pour le demandeur

Appliquer d’abord le [contrat commun](../audit-method/SKILL.md).

Demander le niveau du demandeur sur le domaine, le code du projet et les concepts concernés, son objectif (comprendre, prioriser ou corriger), ses préférences de profondeur et les formats de lecture. Réutiliser les informations du cadrage ; poser uniquement les questions manquantes et attendre les réponses avant d’adapter.

Transformer le dossier brut validé en guide personnel : contexte et vocabulaire utiles, explication des problèmes, impact concret, exemples/pseudocode clairement distingués du code réel, ordre de correction suggéré et critères pour vérifier ultérieurement la correction. Garder les identifiants Axxx, scores, confiance, preuves, limites et couverture. Ne pas faire croire qu’un exemple a été appliqué ou testé. Pour une personne expérimentée, aller directement aux contrats et arbitrages ; pour une personne débutante sur le sujet, expliquer le pourquoi avec des analogies bornées.

Livrer un document autonome exportable dans le ou les formats retenus. Inclure une correspondance exhaustive des Axxx du brut ; si le guide approfondit seulement certains points, conserver la liste complète et indiquer où trouver les autres. Ne pas ajouter de nouveaux constats sans retour à l’étape Audit.
