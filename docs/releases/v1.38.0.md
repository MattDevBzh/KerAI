# Feature Studio 1.38.0

Le parcours quotidien devient plus direct : prépare une tâche pendant qu’une autre avance, garde ton brouillon, puis crée et démarre avec les validations que tu as choisies.

- **Garder la main** : préciser une instruction en cours de travail, arrêter même pendant un envoi, conserver une nouvelle direction et reprendre explicitement.
- **Avancer** : consignes épinglées avec historique, récapitulatif de reprise, citation de messages ou de code, validation et lancement de l’étape suivante.
- **Lire l’utile** : trois onglets principaux — Conversation, Résultat, Modifications — et les détails techniques au second niveau. Historique des étapes et tentatives consultable sans fusionner les conversations natives des agents.
- **Rester dans le QG** : popin des questions et permissions, brouillon partagé avec le chat, volet d’intervention et de lecture, validation et correction.
- **Ouvrir plus tôt** : panneau affiché avant la préparation, projet actif prioritaire, chargements secondaires bornés, états partiels explicites, diagnostic local. Les inspections Git complètes de Livraison et les discussions sont chargées à leur utilisation.

Les protections Git, les permissions et les validations humaines restent appliquées. Arrêter conserve les modifications déjà faites. Une consigne reçue ne signifie pas qu’elle a déjà été appliquée.

Les deux projets Windows de l’utilisateur n’étaient pas accessibles. Les mesures publiées portent sur un scénario local synthétique ; la vérification du paquet sous Windows est automatisée dans GitHub Actions. Les objectifs de délai sur sa machine ne sont pas présentés comme acquis.
