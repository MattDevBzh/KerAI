# Feature Studio 1.38.1

Dans Applications, un échec à l’ouverture du navigateur indiquait « vérifiez la cible et l’état de la page », même quand aucune fenêtre ne s’ouvrait. Le message précise maintenant l’étape concernée : vérification de l’exécutable, lancement, préparation de la session ou chargement du site.

- Les erreurs reconnues expliquent un profil déjà utilisé, un accès refusé, un navigateur fermé au démarrage, un problème HTTPS, un serveur inaccessible, une adresse introuvable, un proxy ou un délai dépassé.
- Le chemin complet du navigateur est consultable dans **Chemin du navigateur**, sous le message de préparation.
- Le panneau **Sortie → Feature Studio** contient des lignes **[Navigateur]** : étapes commencées ou échouées, durées, système, version du moteur, codes réseau ou système et code de sortie disponibles. Les URL, chemins privés et arguments ne sont pas journalisés.
- Une erreur pendant la vérification remplace correctement le message d’attente. Le lancement dispose de son propre délai pour renvoyer son diagnostic avant celui du transport.
- Les détails sensibles des journaux Playwright restent masqués. Les contrôles HTTPS restent actifs.
- La validation Windows ouvre désormais le navigateur depuis le paquet VSIX chargé dans VS Code, puis vérifie l’inspection, la capture et le rejeu sur une application locale synthétique.

Cette version corrige le diagnostic trompeur. Le blocage signalé sur le poste Windows de l’utilisateur et son application HTTPS privée n’a pas été reproduit ; sa cause reste à confirmer avec le nouveau message et le chemin du navigateur.
