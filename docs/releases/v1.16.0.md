# Feature Studio 1.16.0 — Des équipes fidèles aux profils d’agents

Les agents d’une feature utilisent désormais les profils du menu **Agents** au lancement, qu’ils aient été ajoutés seuls ou depuis une équipe.

- Instructions, skills, outils, permissions, contexte par défaut et ton proviennent du profil courant.
- Dans une équipe, seuls le **modèle** et la **réflexion** sont personnalisables pour chaque membre. Les autres paramètres sont visibles en lecture seule.
- Un champ **Hériter de l’agent** reste vide dans l’équipe et reprend la valeur du profil au lancement. Les deux champs héritent indépendamment.
- Le menu **Agents** permet de définir les permissions et la réflexion par défaut. Un profil modifié après un aperçu impose de recalculer cet aperçu avant exécution.
- L’ordre des interventions, les dépendances et leur participation obligatoire ou facultative restent configurables. Un profil de modèle activé explicitement dans le budget de la feature conserve sa priorité.

Les modèles d’équipes existants sont adaptés à leur lecture. Pour une ancienne feature encore modifiable, ouvre **Modifier l’équipe**, puis valide pour bénéficier du nouvel héritage. Les sessions verrouillées et les tentatives passées conservent leur configuration ; une nouvelle session utilise le nouveau fonctionnement.

Télécharger le VSIX ci-dessous, utiliser **Extensions : Installer à partir du VSIX**, puis recharger la fenêtre. [Guide de l’héritage](../GUIDE.md#héritage-des-profils-dans-une-équipe).

Les tests de régression couvrent les profils personnels, les remplacements indépendants, les skills périmées, les changements de profil avant lancement et les formulaires d’équipe.
