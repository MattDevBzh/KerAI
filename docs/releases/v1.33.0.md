# Feature Studio 1.33.0 — Boucles de correction vérifiables

Le pilote peut désormais comparer les résultats de ses corrections et s'arrêter lorsqu'il stagne, au lieu de consommer tous les cycles sans expliquer ce qui a changé.

- **Contrat figé** au premier démarrage : besoin, critères, commandes de test et parcours. Une modification attend un renouvellement humain explicite avant la prochaine exécution automatique.
- **Suivi des progrès** par contrôle, avec problèmes nouveaux, persistants et levés, tentative et preuves associées. Les constats du relecteur restent distincts des résultats de tests hôtes.
- **Arrêts explicites** pour stagnation, oscillation, contrat modifié ou historique plein. Les points de validation, permissions et plafonds existants restent prioritaires.
- **Historique conservé** lors du renouvellement, sans remise à zéro des budgets ni lancement implicite. Bilan dans le cockpit et l'export Markdown, migration du stockage vers la version 13.

Pour essayer : ajoute un critère observable, configure une route de correction et ses limites, puis active **Suivre les progrès de la boucle** dans les réglages du pilote. Garde la validation du code avant les tests et relis l'aperçu de lancement.

[Guide complet](https://github.com/MattDevBzh/KerAI/blob/v1.33.0/docs/BOUCLES-CORRECTION.md)

Cette version conserve une tentative active par cockpit et les validations humaines obligatoires des sous-équipes. Les tests de régression vérifient le contrat, les preuves, les arrêts et les reprises ; ils ne constituent pas une mesure de productivité sur plusieurs tickets réels.
