# Feature Studio 1.36.0 — Relecture dédiée

- Une entrée **Relecture** ouvre une liste distincte des sessions, avec recherche, filtres, archives et gestion groupée.
- La création demande uniquement un projet et une cible : modifications non commitées, source/destination Git, ou URL de Pull Request.
- L’écran de travail conserve la composition d’équipe et les réglages des sessions. Les paramètres du projet permettent de choisir un relecteur par défaut pour les PR et un autre pour Git.
- Au lancement, le contexte complémentaire est facultatif. La cible reste toujours transmise ; les résultats et le récapitulatif sont conservés dans la relecture.
- Les relectures sont en lecture seule : aucune modification du code, exécution de tests ou publication de commentaire par les outils dédiés.

## Accès aux sources

La comparaison Git utilise l’ancêtre commun vers la branche source, indépendamment de la branche courante et sans checkout. Seules les branches locales et les références distantes déjà connues sont proposées.

Les URLs GitHub et Azure DevOps sont prises en charge. GitHub nécessite `gh` installé et authentifié ; Azure DevOps utilise la connexion KerAI du même projet et de la même organisation. Les fichiers sont lus aux commits identifiés. Les erreurs d’accès, changements de révision et limites de pagination sont explicites. Les PR GitHub de plus de 3000 fichiers ne peuvent pas être entièrement inventoriées avec cet endpoint.

## Compatibilité

Le stockage passe en version 15, avec migration des versions 0 à 14. Une ancienne extension refuse ce nouveau format plutôt que de perdre la cible des relectures. Les fonctionnalités de la 1.35.0 sont conservées.
