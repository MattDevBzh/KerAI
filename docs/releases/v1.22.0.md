# Feature Studio 1.22.0 — Copilot natif

Les nouvelles sessions laissent Copilot utiliser ses outils de lecture, recherche, édition, terminal et questions humaines. Feature Studio conserve l’équipe, les parcours, le QG et les validations, avec les outils métier existants.

Les permissions se choisissent à la création, avant le lancement et pendant le travail : **Manuel**, **Assisté** quand le runtime l’autorise, ou **Tout autoriser**. Ce choix est indépendant du solo/pair. Une demande affiche l’action concernée et propose un accord unique ou un refus. Les règles imposées par Copilot restent prioritaires.

La section **Preuves** montre les événements natifs avec commande, dossier, sortie et code de retour lorsqu’il est fourni sous forme structurée. Les fichiers observés sont conservés, y compris après annulation ; ils ne deviennent pas une attribution exclusive à l’agent. Les preuves métier restent séparées.

Le couple vérifié est **CLI 1.0.102 / SDK 1.0.20**. Le CLI 1.0.63 ne fournit pas les APIs requises. Sur le runtime testé, Manuel et Tout autoriser sont disponibles, mais Assisté est désactivé : l’interface reflète cette limite. Après mise à jour du CLI, relance le diagnostic depuis les réglages.

Le stockage passe à la version 8 pour préserver les permissions et activités natives. Les sessions anciennes ne changent pas automatiquement de régime ; leur migration complète ne fait pas partie de ce lot. Le passage généralisé solo/pair et la continuité native de conversation constituent le lot 2.

La recette comprend des tests automatisés, un vrai runtime sans inférence, une correction avec un modèle réel et un processus enfant arrêté sur annulation. Les vérifications du paquet, de VS Code et des jobs Linux/Windows sont les étapes distinctes de publication. [Guide et limites](../COPILOT-NATIF.md) · [Preuve du runtime](../native-runtime-proof.json).

Validation locale : 709 tests réussis (5 tests optionnels ignorés), 237 scénarios d’interface vérifiés, 2 tests supplémentaires sur le vrai CLI sans inférence. Les essais d’archives et de restauration ayant dépassé leur délai lors du premier passage concurrent sont passés isolément puis dans la suite complète seule.
