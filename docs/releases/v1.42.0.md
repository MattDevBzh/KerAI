# Feature Studio 1.42.0 — Préparer et accompagner sa PR avec un agent

Le bouton **Préparer la PR** ouvre la livraison sur la branche et dans l’espace de travail de la session. Une session multi-projets propose une entrée par dépôt.

- **Agent dédié** : un profil Rédacteur de PR est fourni. Choisis ton profil dans les réglages de PR ; son modèle et ses instructions sont utilisés, avec les consignes propres au dépôt.
- **Réglages durables** : branche cible, consignes ou modèle de description, brouillon par défaut et relecteurs habituels, séparés par organisation/projet/dépôt.
- **Rédaction automatique** : à la première ouverture, si le code est commité et Azure connecté, l’agent propose un titre et une description à partir du diff et des preuves de session. La génération peut être arrêtée ou relancée ; les corrections manuelles restent conservées.
- **Formulaire relu avant création** : cible, titre, description, ticket associé, relecteurs avec statut obligatoire, brouillon ou PR prête à relire. Commit et push restent accessibles dans le même écran.
- **Reprise fiable** : un changement de code invalide une rédaction en cours. La création exige le commit présent sur Azure ; une PR déjà ouverte pour les branches choisies est retrouvée, y compris après une réponse de création perdue.

La rédaction consomme les crédits du fournisseur choisi. Elle n’a aucun outil Git, shell, MCP ou de publication. Le diff fourni est limité à 400 fichiers et 100 000 caractères ; les chemins sensibles sont exclus et toute comparaison partielle est signalée à l’agent. Les tests automatisés utilisent des réponses Azure et d’agent simulées : ils ne remplacent pas la recette sur un compte Azure réel ni l’évaluation du texte d’un modèle réel.

La recherche de relecteurs nécessite **Identity en lecture** en plus des droits Code et Work Items habituels. Aucun vote, fusion ou auto-complétion n’est lancé.

## Accompagner une PR existante

Depuis la livraison de la session, **Intervenir sur une PR avec un agent** permet de choisir le profil Pull Request Administrator (ou un autre profil), d’enregistrer ses instructions, les règles et le contexte propres à la session, puis de préparer les interventions sur une PR du même dépôt et de la même branche.

- Autoriser séparément les commentaires, le titre et la description. Le code publié et les preuves de session servent de contexte ; les fichiers locaux non commités ne sont pas utilisés.
- Relire les propositions et leurs blocs de code, modifier les textes et sélectionner ceux à publier. Aucune proposition n’est cochée automatiquement. Le nombre de blocs sans annotation et les exclusions sont affichés.
- Choisir le statut des **nouveaux fils** : By design (par défaut), Won’t fix, Active ou Closed. Ce choix ne change jamais le statut d’un fil existant.
- Reprendre sans dupliquer les annotations reconnues. Seul le commentaire créé par KerAI et resté intact peut être modifié. Une réponse humaine, une modification du texte, du statut ou de l’emplacement protègent le fil.
- Recontrôler la PR et ses champs avant publication. Un changement interrompt les actions restantes ; les opérations réussies ne sont pas annulées. Une création au résultat incertain est recherchée dans Azure et n’est jamais renvoyée aveuglément.

Cette version traite les blocs textuels vérifiables, avec un maximum de 400 fichiers, 100 blocs, 100 000 caractères de diff et 50 propositions de commentaires. Les renommages sont signalés et laissés à la relecture manuelle. Les noms de règles doivent figurer dans les instructions ou le contexte fourni ; cette correspondance n’atteste pas leur bonne application ni une conformité de sécurité. La description modifiée est limitée à 4 000 caractères.

Les publications nécessitent les droits Azure de modification du code/PR et de discussion. Aucun vote, fusion, changement de branche cible ou réponse automatique à une discussion humaine n’est proposé. Les contrôles juste avant écriture réduisent les conflits mais ne rendent pas une série de requêtes Azure atomique.
