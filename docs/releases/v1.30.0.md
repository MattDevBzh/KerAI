# Feature Studio 1.30.0 — Pilote automatique vérifiable

Le pilote dispose de trois profils : valider chaque étape, valider le plan et la revue, ou enchaîner jusqu’au bilan. Avant de démarrer, un aperçu présente la prochaine action, les arrêts humains, le contexte transmis et les exécutions restantes. Les permissions Copilot restent réglées séparément et la validation définitive reste humaine.

- Une demande de navigation met immédiatement le pilote en pause. Le contexte de navigation de la session est transmis aux étapes, sauf exclusion explicite.
- Les tests natifs peuvent produire des preuves vérifiées, liées à une commande configurée et à l’état des fichiers. Si le CLI ne fournit pas de code de sortie structuré, KerAI réexécute cette commande localement, sans nouvel appel IA ; cette vérification est annoncée et identifiée dans la preuve.
- La configuration DevOps s’enregistre avant de disposer des résultats du test hors production. L’étape concernée conserve son lancement manuel et ses justificatifs obligatoires.
- Un échec d’enregistrement conserve la saisie. Reconfigurer le pilote conserve les compteurs ; un refus avant l’appel IA ne consomme plus de cycle de correction.
- Un journal garde les 200 dernières décisions. Les pauses donnent accès à l’étape concernée ; « Demander la pause » laisse finir la tentative et « Arrêter maintenant » l’annule.

Les preuves natives exigent une commande synchrone reconnue sans ambiguïté et des fichiers inchangés. Les commandes complexes et les rapports qualité restent vérifiés par les outils de tests hôte. L’inventaire est borné à 5 000 fichiers, 8 Mo par fichier et 64 Mo au total ; il ne couvre pas les dépendances ignorées par Git ni les services externes.

Le stockage passe en version 12 avec migration des anciennes sessions. Une ancienne version de KerAI ne peut pas relire le nouveau format.

Validation locale : **974 tests de logique/intégration**, **7 tests avec le CLI de référence 1.0.102** et **291 scénarios Chromium** réussis après correction du débordement mobile et relance séparée de trois tests de disque/Git ayant dépassé leur délai. TypeScript, mise en forme, construction, intégrité du VSIX et chargement dans VS Code Insiders sur macOS vérifiés.

La publication exige aussi les validations Linux et Windows, les contrôles du vrai CLI avec un fournisseur local déterministe, le chargement du VSIX dans VS Code et la vérification des empreintes des fichiers publiés. Ces contrôles ne mesurent pas la qualité des réponses d’un modèle réel.

Installe `feature-studio-1.30.0.vsix`, puis recharge VS Code. Dans une session, ouvre **Configurer** sur le pilote, choisis ton profil et consulte l’aperçu avant de démarrer.
