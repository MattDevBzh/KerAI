# Feature Studio 1.42.1 — Commit fiable et livraison plus lisible

Cette version corrige un blocage de création de commit : une simple actualisation de l’index Git par l’éditeur pouvait faire rejeter l’aperçu alors que le contenu n’avait pas changé. Les changements réels de fichiers, de sélection Git ou de branche restent contrôlés avant validation.

- **Chaque action donne un résultat visible** : attente de la confirmation VS Code, travail en cours, annulation, erreur ou succès avec le commit concerné. Les erreurs Git et Azure expliquent les causes reconnues et les actions possibles.
- **Livraison réorganisée** : étapes Commit → Push → PR, aperçu à côté de l’action, détails avancés repliés et raisons des boutons indisponibles. Le push indique le commit envoyé et signale les fichiers encore non commités.
- **PR plus robustes** : prise en charge des fils système et commentaires supprimés d’Azure, diagnostic des PR inactives et des comparaisons indisponibles, actualisation des sources de contexte et suivi de la préparation par l’agent.
- **Réessai après erreur** : un refus explicite d’Azure ne bloque plus définitivement la publication. Les réponses réseau incertaines restent vérifiées avant de renvoyer un commentaire, afin d’éviter les doublons ; les discussions reprises par un humain restent protégées.

Validation locale : **1 291 tests de logique/intégration réussis**, 11 conditionnels ignorés, et **19 scénarios d’interface ciblés réussis**, avec contrôle des types et compilation. Les régressions couvrent notamment un vrai commit après actualisation de l’index et un push vers un dépôt Git local. La publication attend les validations Linux et Windows et la vérification du paquet installable.

Les échanges Azure et les réponses d’agent sont simulés dans ces tests. La recette avec les droits, politiques et modèles du compte réel reste à faire.

Pour tester : installer le VSIX **1.42.1**, recharger la fenêtre VS Code, puis préparer et valider un commit depuis la livraison. Le résultat affiche son identifiant ; le push doit annoncer ce même commit avant de poursuivre vers la PR.
