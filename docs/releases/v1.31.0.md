# Feature Studio 1.31.0 — Worktrees et réponses de l’autopilot

La création d’une feature dans un nouveau worktree ne coupe plus systématiquement Git après trente secondes. Le checkout peut durer jusqu’à dix minutes ; les lectures disposent de deux minutes. Les erreurs distinguent le délai dépassé, une interruption externe et une erreur Git, avec le dossier et la branche concernés.

L’autopilot reprend après la dernière réponse attendue, y compris lorsqu’une question arrive à la fin d’une tentative. Une autorisation accordée permet également la reprise ; un refus maintient la pause. Le bouton **Rester en pause**, l’arrêt et le redémarrage empêchent toute reprise automatique.

Un unique choix explicitement marqué **Recommandé** ou **Recommended** peut être retenu automatiquement. Une question libre, sans recommandation ou avec plusieurs recommandations attend une réponse humaine. Cette sélection ne traite pas les demandes de permission.

Le bouton **Réponses automatiques** ouvre un récapitulatif des 200 dernières réponses : question, réponse sélectionnée, étape et date. Il reste consultable après reconfiguration et réouverture. Les plafonds d’exécution, critères, validations humaines et preuves restent applicables.

Les tests ciblés couvrent les délais Git simulés, l’isolation réelle du worktree, les questions successives et simultanées, la reprise des réponses finales, les permissions, le stockage et le récapitulatif sur grand et petit écran. La compilation et l’archive VSIX sont vérifiées séparément ; une recette sur le dépôt Windows de l’utilisateur reste nécessaire pour mesurer le temps réel du checkout.

La vérification visuelle locale reste incomplète : Chromium s’arrête dans son moteur de polices avant l’ouverture des écrans. Les scénarios desktop/mobile sont ajoutés aux tests d’interface de la CI ; aucun succès visuel local n’est revendiqué.
