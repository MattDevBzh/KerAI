# Feature Studio 1.5.0 — Discussions et navigation

Cette version ajoute un espace pour échanger librement avec les agents, réorganise les menus et place le choix du projet dans les écrans où il est utile.

## Discussion

- Menu juste après **Dashboard**, avec historique à gauche, regroupé par date et accessible après rechargement de VS Code.
- Agent au choix ; modèle et raisonnement ajustables pour chaque conversation, sans changer les valeurs du profil.
- Messages humains à droite, réponses progressives à gauche avec l’avatar de l’agent, couleurs adaptées aux thèmes et au contraste élevé.
- Recherche d’une conversation, arrêt d’une réponse et suppression confirmée de l’historique.
- Case **Agent de discussion** à la création et dans l’éditeur des agents. Les profils cochés apparaissent en priorité ; **Voir plus** présente les autres.
- Les instructions, skills et ton du profil accompagnent les messages. Le chat n’accède pas automatiquement aux fichiers du projet et n’exécute pas d’outils.
- Les mesures reçues pour les discussions sont incluses dans **Consommation**.

## Projets et parcours

Les menus suivent l’ordre : **Dashboard → Discussion → Validation → Consommation → Parcours → Agents → Skills → Automatisations → Kits → Réglages → Livraison → Azure DevOps (PR, Tickets) → Mémoire**.

Les vues globales n’affichent plus de sélecteur de projet. Les profils locaux, la mémoire et les connexions Azure DevOps conservent leur contexte de projet. La création d’une feature garde son propre choix de dossiers.

Dans **Réglages**, le commun vient en premier : thèmes, connexion Copilot, gestion des dossiers et raccourci. Une liste déroulante sous **Paramètres par projet** sélectionne ensuite les paramètres du dépôt. Un brouillon doit être enregistré ou annulé avant de changer de projet. Les sauvegardes portent explicitement l’identifiant du projet affiché.

Le bouton **Supprimer** des parcours retire le modèle du catalogue personnel après confirmation. Les sessions existantes et les fichiers de définition sont conservés. Réenregistrer la définition restaure son entrée dans le catalogue.

## Installation et vérification

Installe **feature-studio-1.5.0.vsix** depuis les assets de cette release avec **Extensions → … → Installer à partir du VSIX…**, puis recharge la fenêtre. La fiche Feature Studio doit afficher **1.5.0**. Aucun changement des données de session existantes n’est requis.

Le logo **L’équipe** et l’icône du raccourci sont conservés. Pour actualiser un raccourci Windows existant, utilise **Réglages → Créer le raccourci Windows**.

La publication attend les validations Linux et Windows du commit livré : format, TypeScript, tests métier, scénarios Chromium, catalogue CLI et smoke VS Code. Le VSIX reconstruit est contrôlé, extrait puis chargé dans un vrai hôte VS Code. Le VSIX et l’ICO téléchargés depuis la release brouillon sont vérifiés contre **SHA256SUMS** avant publication. Le lien vers le run exact est ajouté par le workflow.

Les tests utilisent des réponses simulées et n’envoient pas de prompt Copilot payant. La connexion et une conversation sur ton compte Copilot restent à vérifier après installation. [Validation et limites](https://github.com/MattDevBzh/KerAI/blob/main/docs/VALIDATION.md).
