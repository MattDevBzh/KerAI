# Démarrer, avancer et garder la main

Dans **Nouvelle session**, décris le besoin, sélectionne les projets, puis choisis le travail en pair ou confié à l’agent. La progression guidée conserve une validation à chaque étape ; la progression équilibrée garde les points de contrôle du plan et du résultat. Les équipes personnalisées conservent un arrêt avant leur première étape d’écriture et à la fin. Les questions et permissions restent humaines.

**Garder en brouillon** permet de préparer autre chose pendant que l’agent travaille. Retrouve ces préparations dans Sessions ou dans le sélecteur du formulaire. Les images, choix de projets et préférences restent avec le brouillon. La création seule prépare la session ; **Créer et démarrer** tente aussi son premier lancement. Si Copilot ou un contexte requis manque, la session créée reste disponible pour reprendre le lancement.

Dans une conversation en pair, envoie une précision pendant l’exécution. **Arrêter** reste disponible même si un message attend sa confirmation. **Arrêter et réorienter** conserve ton nouveau cap et attend ta reprise ; les modifications déjà faites restent sur disque.

Les **Consignes épinglées** portent sur la tâche ou sur le projet principal. Chaque modification possède une version et un historique. Une consigne ne change jamais les permissions. Si une direction doit être interrompue immédiatement, utilise l’arrêt plutôt que de supposer que l’agent a déjà appliqué le message.

Le fil de la tâche conserve les échanges précédents. **Répondre à ce passage** cite un message ; **Joindre la sélection de code** récupère la sélection de l’éditeur VS Code et signale si le fichier a changé avant l’envoi. Les contextes natifs des différents agents restent distincts.

Après lecture, **Valider et lancer la suite** approuve l’étape puis prépare la suivante. Si cette préparation échoue, l’approbation n’est pas perdue. Le bouton de validation seule reste disponible.

Dans le QG grand écran, les demandes apparaissent directement dans une popin. **Plus tard** conserve la saisie ; le bouton des demandes en attente permet de la retrouver. **Intervenir** ouvre le chat dans un volet, **Relire le résultat** donne accès au compte rendu, à la validation et aux corrections sans quitter le QG.

À l’ouverture, le projet actif devient disponible avant les autres. Une indication précise si les listes sont encore partielles. Chaque projet en erreur peut être réessayé. Livraison inspecte les changements quand tu ouvres son écran. Les diagnostics de démarrage sont locaux, dans la sortie **Feature Studio** et le fichier `startup-diagnostics.json` du stockage global de l’extension.
